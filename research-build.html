The build phase is no longer the bottleneck

How Meraxis Labs uses AI-assisted development, and where human judgement still decides what ships.

A working prototype used to be the scarce resource. It is not, for this lab. AI-assisted implementation can turn a specified flow into something a design partner can click within days. That shift moved the constraint from “can we build it?” to “should we build it?”

The work that did not compress is the work before the editor opens. Who has the problem, how often, what they do today, and what evidence would make us archive the experiment. Those questions still take conversations, not generations.

What we changed in practice

Engineers spend less time on scaffolding and more time on the domain rule that would make the product wrong if it were fuzzy. For Pay, that rule is “usage and subscriptions settle on one invoice.” For Scan, it is “a bad image is a retake, not a rejection.” For Vault, it is “every read is an event someone can query.”

Speed is useful only if the kill criterion is already written. Otherwise the lab just fails faster and then rationalizes a pivot. The methodology page is the operating version of this note.
